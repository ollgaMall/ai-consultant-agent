## 3. Архитектурные решения

### 3.1 Транскрипция (REQ-05.1)
**Решение:** GigaAM-v3 (self-hosted, MIT) — основной; Whisper (self-hosted) — резерв.
**Обоснование:** GigaAM-v3 существенно точнее на русском (WER 9.2% vs 25.1% у Whisper-large-v3, официальный бенчмарк модели). Оба варианта — self-hosted, без лимитов и платных зависимостей.
**Важная находка:** референс ТЗ v1.2 о бесплатном тарифе Yandex SpeechKit (100 000 сообщений/мес) не подтверждён официальной документацией — реально бесплатен только пробный период, далее платно. Зафиксировано как ошибка исходного research в `lessons-learned.md`.
**Отклонено:** Yandex SpeechKit (нет постоянного free tier), mymeet.ai (лимит 180 мин/мес исчерпывается на одном клиенте), TurboScribe (лимит файлов/день).

### 3.2 Хранилище эталона (REQ-18)
**Решение:** ChromaDB (self-hosted, Apache 2.0) с локальной embedding-моделью (`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, без OpenAI API).
**История решения:** Архитектор изначально рекомендовал JSON-библиотеку (YAGNI-обоснование). Владелец продукта переопределил решение в пользу ChromaDB. После введения RAG-пайплайна (волна 3) это решение подтвердилось как более дальновидное — маржинальная стоимость переиспользования уже поднятой инфраструктуры ChromaDB для RAG оказалась ниже, чем стоимость отдельного JSON-решения. Архитектор признал ошибку изолированной оценки задачи (см. `lessons-learned.md`).
**Отклонено:** JSON-библиотека (первоначальная рекомендация, отменена), графовая БД.

### 3.3 LLM-провайдер для аналитического слоя (REQ-07–12)
**Решение:** Переключаемая комбинация — Gemini API (free tier, прямой), OpenRouter (:free модели), опционально Groq — через единый интерфейс `AnalysisLLMProvider` (Provider abstraction).
**Обоснование:** Независимые лимиты каждого провайдера дают реальную возможность «переключаться, пока не кончатся токены» — в отличие от использования только OpenRouter, где лимит (20 запросов/мин, 50/день) общий на аккаунт для всех моделей сразу, а не per-модель.
**Риск конфиденциальности:** free tier Gemini использует данные запросов для обучения — принято условие: реальные клиентские данные не передаются до перехода на платный tier/self-hosted LLM. MVP-разработка — только на синтетических/обезличенных данных.
**Отклонено:** GigaChat API (разовый грант 1 млн токенов/год, исчерпывается быстро), OpenRouter как единственный источник (общий лимит не даёт независимости).

### 3.4 RAG-пайплайн для клиентских документов
**Решение:** Голый Python поверх ChromaDB (chunking → embedding → retrieval), НЕ LangChain/LlamaIndex.
**Обоснование:** Образовательная цель владельца продукта (понять механику RAG) + снятие ограничения контекстного окна LLM при росте объёма документов на клиента. Прозрачность реализации важнее готовых абстракций фреймворков.
**Изоляция данных:** отдельная ChromaDB-коллекция на каждый client_id (TASK-028), физически отделена от коллекции эталона (TASK-022) — разное назначение (сырые чанки конкретного клиента vs обезличенные паттерны между клиентами) и разный жизненный цикл (RAG-индекс удаляется по запросу клиента, эталон — постоянный).
**Отклонено:** LangChain/LlamaIndex (скрывают механику, избыточные абстракции для образовательной цели), embedding через OpenAI API (платно, нарушает НФТ Portability).

### 3.5 Точка ручной проверки консультантом
**Решение:** Обязательный гейт (TASK-025/026) между блоком анализа и генерацией отчёта. Формат — структурированный YAML-файл с реальным текстом source-чанков (не chunk_id), редактируемый консультантом в текстовом редакторе.
**Обоснование:** AI-субагенты выдают вероятностный результат — нужна контрольная точка перед финализацией клиентского отчёта. Это пробел исходного ТЗ v1.2, не покрытый ни одним REQ — зафиксировано в `lessons-learned.md` как упущение elicitation-этапа для продуктов с probabilistic-компонентами.
**Обучающий контур:** правки консультанта (TASK-026) — второй источник обучающего сигнала для TASK-024 наравне с фидбеком клиента (REQ-20), равные веса на MVP.

### 3.6 Разделение хранилищ (Polyglot persistence)
**Решение:** ChromaDB — только TASK-022 (эталон) и TASK-028 (RAG-индекс клиента). **SQLite** — все структурные сущности: `CLIENT`, `CLIENT_APPLICATION` (+статус), `USER`, `REPORT`, `REVIEW_EDIT`, `LLM_PROVIDER_CONFIG`.
**Обоснование:** Разные типы запросов требуют разных БД — семантический поиск (ChromaDB) принципиально не то же самое, что точные фильтры/транзакции/целостность (SQLite). MySQL отклонён как избыточный (требует отдельного сервера) — SQLite полностью самодостаточен файлом на диске.

### 3.7 Резервное копирование (новое НФТ)
**Решение:** Ежедневный автоматический архив (ChromaDB snapshot + SQLite + `history/`), копия на второй носитель, ротация 7 дней (TASK-031).
**Обоснование:** Эталон и данные заявок клиентов — единственные невосстановимые компоненты системы (не пересоздаются из исходников). Offsite-копия в облако отложена как не требуемая для MVP.

### 3.8 Заявка и статусная модель
**Решение:** Новая сущность `CLIENT_APPLICATION` с полем `status` (11 состояний, см. раздел 7), SQLite-хранение, матрица допустимых переходов в конфиге (TASK-030).
**Обоснование:** Прозрачность процесса диагностики для клиента и консультанта.

### 3.9 Telegram-бот — анти-спам
**Решение:** Приём свободного текста только в ожидаемом состоянии диалога + ограничение длины ответа (500 символов, конфигурируемо). Явно НЕ добавлены: rate limit на пользователя, глобальный rate limit сообщений/сек, CAPTCHA.
**Обоснование:** Узкий сценарий (кнопки + один свободный текстовый ответ) не требует более тяжёлой защиты.

### 3.10 Единое веб-приложение (Вариант Б)
**Решение:** Flask + Jinja2 + htmx, серверный рендеринг, WSGI-сервер waitress. Раздельная аутентификация: логин/пароль (Консультант, Администратор) через Flask-Login; magic-link (временная подписанная ссылка, `itsdangerous`) — Клиент, Сотрудник клиента.
**Обоснование:** Единый веб-слой строится один раз вместо патчворка файлов/бота/CLI по каждой отдельной точке взаимодействия. Magic-link избавляет разовых внешних пользователей от регистрации.
**Следствие:** ранее специфицированная задача TASK-033 (изолированный Flask-сервис только для переключения LLM-провайдера) **упразднена** — функциональность становится экраном №9 внутри единого веб-приложения (см. раздел 8).
**Отклонено:** SPA на React (лишний build-процесс для self-hosted MVP), единый логин для всех ролей включая внешних пользователей.
