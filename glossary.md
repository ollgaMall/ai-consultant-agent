# glossary.md

**Последнее обновление:** 08.09.2026

Три слоя терминов: (1) доменные термины продукта, (2) термины архитектуры мультиагентной системы (процесс разработки), (3) термины архитектуры данных и UI самого продукта.

---

## Слой 1. Доменные термины продукта

| Термин | Определение | Где используется |
|---|---|---|
| **AI Opportunity and Implementation Consultant** | Название продукта: система бизнес-диагностики произвольной компании, выявляющая узкие места процессов и возможности внедрения AI | README.md |
| **Бизнес-диагностика** | Итоговый артефакт системы — отчёт или «книга», описывающая текущее состояние компании и рекомендации к изменению | README.md, ТЗ от Perplexity |
| **Карта AI-возможностей** (AI Opportunity Map) | Часть выходного отчёта: перечень процессов-кандидатов для внедрения AI-агентов с обоснованием приоритета | README.md |
| **As-is процесс** | Описание бизнес-процесса компании в его текущем, ещё не изменённом состоянии — часть входных данных | README.md |
| **Владелец продукта** | Роль пользователя (Ольга) в момент, когда она выступает единственным доступным стейкхолдером для определения требований к самому продукту (TASK-000) | role-perplexity.md, раздел 1.6 |
| **Business Diagnostic Agent (BDA)** | Отдельный проект владельца продукта — методология/архитектурный трек, с помощью которого строится архитектура для продукта AI Opportunity and Implementation Consultant. Не тождественен текущему продукту | decisions-log.md, status-current.md |
| **deliverables/** | Папка для полных текстов крупных документов-артефактов (ТЗ, архитектура) — по одному файлу на версию, без перезаписи | README.md, role-perplexity.md, role-claude.md |
| **Книга диагностики** | Итоговый отчёт системы (~20 страниц MVP) со структурой: Executive Summary, AS-IS, TO-BE, Карта процессов, Дорожная карта, ROI | ТЗ от Perplexity (TASK-000) |
| **Чек-лист зрелости 0–5** | Шкала оценки AI-экосистемы клиента | ТЗ от Perplexity |
| **manifest.md** | Реестр входных материалов клиента (путь, тип, batch ID, описание) | ТЗ от Perplexity (REQ-03) |
| **Digest по сотруднику** | Структурированная выжимка из транскрипта: роль, процессы, инструменты, боли, метрики, ASR-неясности | ТЗ от Perplexity (REQ-05) |
| **Telegram-бот пред-квалификации** | Бот для краткой диагностики потенциального клиента (3 вопроса) | ТЗ от Perplexity (REQ-19), TASK-023 |

|---|---|---|

| **Дельта изменений** | Блок ADDED/MODIFIED/REMOVED, описывающий изменения относительно предыдущего снапшота | Все role-*.md |
| **Снапшот** | Копия `status-current.md` с таймстампом в `history/` | status-current.md |
| **Generator** | Роль DeepSeek — генератор кода | role-deepseek.md |
| **Evaluator** | Роль ChatGPT — независимый ревьюер кода | role-chatgpt.md |
| **Арбитр** | Режим Claude при неразрешённом конфликте Generator↔Evaluator за 3 итерации | role-claude.md, 2.4 |
| **TASK-XXX** | Идентификатор атомарной задачи в цепочке хендоффа | role-claude.md, role-perplexity.md |
| **Stakeholder Interview (Этап 0)** | Elicitation-режим у Perplexity перед research | role-perplexity.md, 1.6, 2.2a |
| **Триггер финальной сборки** | Явная команда, заставляющая агента выдать итог одним блоком | Все role-*.md |
| **Pre-flight checklist** | Список файлов, обязательных к прочтению до начала работы | Все role-*.md, 2.1 |
| **Post-flight actions** | Черновики обновлений status/glossary/decisions-log в конце сессии | role-perplexity.md, 2.4 |
| **Definition of Done (DoD)** | Критерии готовности задачи к приёмке | role-claude.md, role-deepseek.md |

| **Проактивный чек-лист архитектора** | Набор из 7 пунктов (хранилище, бэкапы, деплой/UI, анти-спам, provider abstraction, верификация free-tier фактов, влияние на прошлые решения), обязательных к проверке Claude при каждом новом архитектурном решении | role-claude.md, 1.6 |

## Слой 3. Термины архитектуры данных и продукта

| Термин | Определение | Где используется |
|---|---|---|
| **RAG (Retrieval-Augmented Generation)** | Паттерн: разбиение документов на чанки → векторизация → поиск релевантных фрагментов по смыслу → передача только их в LLM, вместо всего объёма документов | TASK-027-029 |
| **Chunk (чанк)** | Фрагмент текста после разбиения документа, с overlap относительно соседних фрагментов | TASK-027 |
| **Retriever** | Компонент, находящий top-K наиболее релевантных чанков по векторному сходству с запросом | TASK-029 |
| **EmbeddingProvider** | Интерфейс (Provider abstraction) для получения векторного представления текста; используется и TASK-022, и TASK-028 | TASK-022, TASK-028 |
| **AnalysisLLMProvider** | Интерфейс для LLM-рассуждения; конкретные реализации — GeminiProvider, OpenRouterProvider, GroqProvider | TASK-009 и далее, TASK-032 |
| **BenchmarkRepository** | Хранилище накопленного эталона — обезличенных паттернов процессов между клиентами (ChromaDB) | TASK-022 |
| **ClientDocumentStore** | Изолированное по client_id RAG-хранилище документов конкретного клиента (ChromaDB, отдельная коллекция) | TASK-028 |
| **Claim / ClaimType** | Атомарное утверждение с обязательной маркировкой: ФАКТ / ВЫВОД / ГИПОТЕЗА / ПРЕДПОЛОЖЕНИЕ | TASK-008 |
| **Точка ручной проверки (Review Gate)** | Обязательный шаг, на котором консультант проверяет и правит результаты AI-анализа перед формированием отчёта | TASK-025/026 |
| **Polyglot persistence** | Использование нескольких типов баз данных под разные задачи в одной системе (ChromaDB — векторный поиск, SQLite — структурные данные) | decisions-log.md, 08.09.2026 |
| **Заявка (Client Application)** | Сущность, отслеживающая процесс диагностики конкретного клиента от создания до закрытия, с явным статусом | TASK-030 |
| **Статус заявки (Application Status)** | Одно из 11 состояний заявки (см. диаграмму статусов); переходы валидируются по явной матрице допустимых переходов | TASK-030 |
| **Service Blueprint** | Диаграмма точек взаимодействия человека с системой по этапам процесса, с разделением front-stage (видимое) / back-stage (система) | service-blueprint.html |
| **Magic link** | Временная подписанная ссылка для доступа без регистрации/пароля — используется клиентом и сотрудником клиента | Веб-приложение, экраны 5, 7, 8 |
| **LLM_PROVIDER_CONFIG** | Сущность, хранящая текущий активный AI-провайдер и модель анализа, читается при каждом вызове анализа (без кэширования на старте процесса) | TASK-032 |
