# glossary.md

**Последнее обновление:** 07.09.2026

Два слоя терминов: (1) доменные термины продукта, (2) термины архитектуры мультиагентной системы.

---

## Слой 1. Доменные термины продукта

| Термин | Определение | Где используется |
|---|---|---|
| **AI Opportunity and Implementation Consultant** | Название продукта: система бизнес-диагностики произвольной компании, выявляющая узкие места процессов и возможности внедрения AI | README.md |
| **Бизнес-диагностика** | Итоговый артефакт системы — отчёт или «книга», описывающая текущее состояние компании и рекомендации к изменению | README.md, ТЗ от Perplexity |
| **Карта AI-возможностей** (AI Opportunity Map) | Часть выходного отчёта: перечень процессов-кандидатов для внедрения AI-агентов с обоснованием приоритета | README.md |
| **As-is процесс** | Описание бизнес-процесса компании в его текущем, ещё не изменённом состоянии — часть входных данных | README.md |
| **Владелец продукта** | Роль пользователя (Ольга) в момент, когда она выступает единственным доступным стейкхолдером для определения требований к самому продукту (TASK-000) | role-perplexity.md, раздел 1.6 |
| **Business Diagnostic Agent (BDA)** | Отдельный проект владельца продукта — методология/архитектурный трек (litellm, LangGraph, ChromaDB и др.), с помощью которого строится архитектура для продукта AI Opportunity and Implementation Consultant. Не тождественен текущему продукту | decisions-log.md, status-current.md |
| **deliverables/** | Папка для полных текстов крупных документов-артефактов (ТЗ, отчёты) — по одному файлу на версию, без перезаписи. Не путать с `history/` (снапшоты статуса) | README.md, role-perplexity.md, раздел 2.3b |
| **Книга диагностики** | Итоговый отчёт системы (~20 страниц MVP) со структурой: Executive Summary, AS-IS, TO-BE, Карта процессов, Дорожная карта, ROI | ТЗ от Perplexity (TASK-000) |
| **Чек-лист зрелости 0–5** | Шкала оценки AI-экосистемы клиента (0 = только идея, 5 = измеримая автономия, комплаенс, фабрика агентов) | ТЗ от Perplexity, файл «Вводные данные» |
| **manifest.md** | Реестр входных материалов клиента, автоматически формируемый системой (путь, тип, batch ID, описание) | ТЗ от Perplexity (REQ-03) |
| **Digest по сотруднику** | Структурированная выжимка из транскрипта голосового сотрудника: роль, процессы, инструменты, боли, метрики, ASR-неясности | ТЗ от Perplexity (REQ-05) |
| **Telegram-бот пред-квалификации** | Бот для краткой диагностики потенциального клиента (3 вопроса: ниша, размер, боль) с интеграцией в основную систему | ТЗ от Perplexity (REQ-19) |

## Слой 2. Термины архитектуры агентов

| Термин | Определение | Где используется |
|---|---|---|
| **Хендофф** | Передача структурированного результата от одного агента к другому по строгому формату | ai-agenty-proekt-vyzhimka.md, все role-*.md |
| **Дельта изменений** | Блок ADDED/MODIFIED/REMOVED, описывающий, что изменилось относительно предыдущего снапшота | Все role-*.md |
| **Снапшот** | Копия `status-current.md` с таймстампом, сохранённая в `history/` перед перезаписью | ai-agenty-proekt-vyzhimka.md, status-current.md |
| **Generator** | Роль DeepSeek — генератор кода на основе задачи от Оркестратора | role-deepseek.md |
| **Evaluator** | Роль ChatGPT — независимый ревьюер кода Generator | role-chatgpt.md |
| **Арбитр** | Режим Claude, включается при неразрешённом конфликте Generator↔Evaluator за 3 итерации; выносит компромиссное решение | role-claude.md, раздел 2.4 |
| **TASK-XXX** | Идентификатор атомарной задачи в цепочке хендоффа (например, TASK-000 — определение требований к продукту) | role-claude.md, role-perplexity.md |
| **Stakeholder Interview (Этап 0)** | Режим elicitation у Perplexity: структурированные вопросы стейкхолдеру ДО начала research, если задача — определить требования к новому продукту | role-perplexity.md, разделы 1.6, 2.2a |
| **Триггер финальной сборки** | Явная команда пользователя агенту, заставляющая выдать итоговый результат одним структурированным блоком, без комментариев вокруг | Все role-*.md, разделы 2.3b/2.4a |
| **Pre-flight checklist** | Список файлов, которые агент обязан прочитать (или запросить) до начала работы над задачей | Все role-*.md, раздел 2.1 |
| **Post-flight actions** | Черновики обновлений `status-current.md` / `glossary.md` / `decisions-log.md`, которые агент предлагает в конце сессии | role-perplexity.md, раздел 2.4 |
| **Definition of Done (DoD)** | Критерии готовности задачи к приёмке (например, покрытие тестами ≥80%, прохождение ревью) | role-claude.md, role-deepseek.md |
| **ТЗ** | Техническое задание — структурированный итоговый документ от Perplexity, формат раздела 2.3 role-perplexity.md | role-perplexity.md, role-claude.md |
