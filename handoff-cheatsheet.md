## Важное разграничение: «база знаний агента» vs «сообщение в чате»

Есть два принципиально разных типа объектов, которые легко перепутать:

| Тип | Примеры | Когда загружается | Меняется ли от задачи к задаче |
|---|---|---|---|
| **База знаний / Custom Instructions агента** | `role-perplexity.md`, `role-claude.md`, `role-deepseek.md`, `role-chatgpt.md`, `role-kimi.md` | Один раз при создании Project/Space для этого агента | Нет — меняется только при коррекции роли через `lessons-learned.md` |
| **Сообщение в чате (вход по конкретной задаче)** | Блок ТЗ, блок ЗАДАЧА ДЛЯ GENERATOR, JSON от DeepSeek, РЕВЬЮ от ChatGPT | Каждый раз заново, под конкретную TASK-XXX | Да — это и есть предмет каждого хендоффа |

Файлы проекта (`status-current.md`, `glossary.md`, `decisions-log.md`, `README.md`, `src/`, `tests/`) — это третья категория: они не загружаются в чат агента как база знаний и не отправляются сообщением, а **редактируются вами напрямую** в репозитории, на основе того, что агент выдал в чате.

## Как читать таблицу

- Строки 1-2 — один раз в начале работы над продуктом (Perplexity, TASK-000 и далее для новых крупных задач).
- Строки 3-9 — повторяются на **каждую** атомарную задачу (TASK-XXX).
- Строка 10 — по завершении **крупного этапа**, не каждой отдельной задачи.
- Строка 11 — не по расписанию, а по факту, когда вы или Claude-Арбитр заметили системную ошибку.

## Правило для всех триггеров

Каждый триггер заставляет агента выдать результат **одним сообщением, без
вступления и комментариев вокруг него** — иначе при копировании легко захватить
незаконченный или промежуточный ответ вместо финального блока.

## deliverables/ vs history/ — не путать

| Папка | Что туда кладётся | Перезаписывается? |
|---|---|---|
| `deliverables/` | Полные тексты крупных документов-артефактов: ТЗ, отчёты. Один файл на версию (`TASK-XXX-TZ-v1.2.md`, затем `v1.3.md` и т.д.) | Нет, никогда — новая версия = новый файл |
| `history/` | Снапшоты `status-current.md` с таймстампом, для отслеживания изменений статуса проекта во времени | Нет, но по другой причине — это архив состояний, не версии документа |
