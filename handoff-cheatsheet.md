## Механизм переноса кода DeepSeek в GitHub (текущий процесс — ручной)

**Важно:** на данный момент это НЕ автоматизировано. Шаги вручную:
1. `git checkout main && git pull && git checkout -b task/TASK-XXX-краткое-название`
2. Записать каждый файл из поля `files` JSON-ответа DeepSeek по указанному пути
3. `git add . && git commit -m "TASK-XXX: краткое summary"`
4. `git push origin task/TASK-XXX-краткое-название`
5. Открыть Pull Request в GitHub (веб-интерфейс или `gh pr create`)
6. После цикла ChatGPT/Kimi/финального QA — Merge PR, удалить ветку

**Открытый вопрос (см. status-current.md):** автоматизировать шаги 1-4 скриптом `apply_generation.py` или оставаться на ручном процессе на текущем объёме задач.

## Важное разграничение: «база знаний агента» vs «сообщение в чате»

| Тип | Примеры | Когда загружается | Меняется ли от задачи к задаче |
|---|---|---|---|
| **База знаний / Custom Instructions агента** | `role-*.md` | Один раз при создании Project/Space | Нет — только при коррекции роли через lessons-learned.md |
| **Сообщение в чате (вход по конкретной задаче)** | Блок ТЗ, ЗАДАЧА ДЛЯ GENERATOR, JSON от DeepSeek, РЕВЬЮ от ChatGPT | Каждый раз заново | Да |

Файлы проекта (`status-current.md`, `glossary.md`, `decisions-log.md`, `README.md`, `config/`, `src/`, `tests/`) — третья категория: не загружаются как база знаний и не отправляются сообщением, а **редактируются вами напрямую** в репозитории.

## Правило для всех триггеров

Каждый триггер заставляет агента выдать результат **одним сообщением, без
вступления и комментариев вокруг него**.

## deliverables/ vs history/ — не путать

| Папка | Что туда кладётся | Перезаписывается? |
|---|---|---|
| `deliverables/` | Полные тексты крупных документов-артефактов: ТЗ, **архитектура Claude** (новое, см. строку 3a), опционально JSON-генерации DeepSeek. Один файл на версию | Нет, никогда |
| `history/` | Снапшоты `status-current.md` с таймстампом | Нет, но это архив состояний, не версии документа |

## НЕ в git (физически на диске, вне репозитория)

`chroma_data/` (ChromaDB), `app.db` (SQLite), `backups/` (локальные архивы TASK-031), `.env` (API-ключи) — см. `.gitignore` и структуру в README.md, раздел 4. Причина: конфиденциальность данных клиента (git помнит удалённые файлы навсегда) и защита секретов.
