### Волна 3 — RAG-пайплайн (по инициативе владельца)
- TASK-027–029: chunking → ChromaDB (изолированные коллекции по client_id) → retriever. TASK-009/011/012/013 обновлены под использование retrieval вместо передачи сырых документов целиком.
- Проведён полный критический пересмотр всей предыдущей архитектуры после введения RAG (см. decisions-log.md, 08.09.2026) — выявлены и закрыты: пробел EmbeddingProvider, устаревание TASK-025 относительно RAG, подтверждена правильность решения владельца по ChromaDB (признана ошибка изначальной рекомендации Архитектора).
- TASK-024 получил второй источник обучающего сигнала — правки консультанта из TASK-026, наравне с фидбеком клиента.

### Волна 4 — НФТ и структурные сущности (по инициативе владельца)
- НФТ по резервному копированию введено — TASK-031 (backup_scheduler): ежедневный архив ChromaDB+SQLite+history, копия на второй носитель, ротация 7 дней.
- Подтверждено разделение хранилищ (polyglot persistence): ChromaDB — только вектор/RAG (TASK-022, TASK-028); **SQLite** — введена как новая реляционная БД для всех структурных сущностей (Заявка, User, Report и т.д.).
- TASK-030: сущность «Заявка» (`CLIENT_APPLICATION`) со статусной моделью из 11 состояний, матрица допустимых переходов.
- LLM-провайдер анализа — расширен с единственного Gemini до переключаемой комбинации Gemini + OpenRouter (:free) + опционально Groq (TASK-032), с независимыми лимитами по провайдерам.
- Telegram-бот дополнен правилами: приём свободного текста только в ожидаемом состоянии диалога, ограничение длины ответа (без rate-limit на пользователя, без глобального rate-limit, без CAPTCHA — явно отклонены владельцем).

### Волна 5 — переход на единое веб-приложение (Вариант Б, по инициативе владельца)
- Принято решение строить полноценное веб-приложение вместо комбинации файлов/CLI/Telegram-бота для внутренних точек взаимодействия: Flask + Jinja2 + htmx, серверный рендеринг.
- Раздельная аутентификация: логин/пароль (консультант, администратор) и magic-link (клиент, сотрудник клиента).
- Спроектировано 13 экранов (Вход, Дашборд, Карточка заявки, Загрузка материалов, Проверка полноты, Анкета сотрудника, Проверка анализа консультантом, Просмотр отчёта, Валидация гипотез, Переключатель LLM-провайдера, Настройка весов скоринга, Управление пользователями, Статус системы/бэкапов) — спецификация экранов дана, декомпозиция в задачи для DeepSeek **ещё не выполнена**.
